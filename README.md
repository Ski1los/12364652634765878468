# ClipLab Local

Самостоятельно разворачиваемый сервис с двумя локальными потоками:

1. **Clip Finder** превращает **доступные вам** YouTube и Twitch VOD/клипы в вертикальные короткие ролики: скачивает источник, локально расшифровывает речь через Whisper, выбирает эмоциональные/смешные/нелепые фрагменты и отдаёт MP4 с вшитыми субтитрами плюс `.srt`.
2. **Story Studio** превращает одну идею в оригинальный Story Reel: локальная LLM пишет сценарий, локальный TTS создаёт озвучку, сервис собирает вертикальное видео с кинетическими сюжетными карточками, субтитрами, заголовком, описанием и хэштегами.

Это лёгкий, независимый local-first аналог [OpenShorts](https://github.com/mutonby/openshorts), сфокусированный на «ссылка → лучшие моменты → готовые клипы» и «идея → оригинальный Story Reel». Он не требует ключа Gemini, OpenAI, ElevenLabs или другого платного API.

> **Честно о «бесплатно».** У приложения нет подписки, лимита, водяного знака или платного облачного API. Расчёт происходит на вашем компьютере/сервере; нужны только его время, электроэнергия, место на диске и интернет для загрузки доступного вам видео и однократной загрузки open-source модели Whisper. Это нельзя гарантированно сделать мгновенно или без аппаратных затрат.

## Что уже работает

- Вставка HTTPS-ссылки на **YouTube**, **Twitch VOD** или Twitch-клип.
- Безопасная allowlist-проверка источника: приложение не скачивает произвольные URL из локальной сети.
- `yt-dlp` загрузка в MP4; поддержка cookie-файла, если у вас есть разрешённый доступ к ролику.
- Локальная расшифровка `faster-whisper` с таймкодами слов (русский и английский в том числе).
- Бесплатный локальный выбор кандидатов: смех, реакции, удивление, экспрессивная и связная речь.
- Необязательное, но более смысловое ранжирование бесплатной **локальной Ollama**-моделью (например, `qwen2.5:7b`).
- 2–6 непересекающихся роликов, 720×1280 или 1080×1920: исходный кадр остаётся целым на размытой вертикальной подложке.
- Крупные контрастные субтитры, уже вшитые в MP4, и отдельный загружаемый SRT.
- Состояние очереди, журнал ошибок, готовые клипы и расшифровка сохраняются в `./data` и не пропадут при перезагрузке страницы.
- Удаление законченной задачи удаляет её исходник, расшифровку и результаты с диска.
- **Story Studio:** идея → оригинальный сценарий из 5–8 сцен → локальная WAV-озвучка → вертикальный MP4 с субтитрами.
- Story Studio сохраняет готовый `content-pack.txt`: заголовок, хук, описание, хэштеги, маркировку AI-assisted и сценарий сцен.
- Озвучка работает локально: eSpeak NG доступен без настройки; необязательная Piper-модель даёт более естественный голос и тоже не использует облако.
- Адаптивный интерфейс с крупными touch-элементами: комфортен на телефоне, планшете и компьютере.

## Быстрый запуск через Docker

Нужны [Docker Engine и Docker Compose](https://docs.docker.com/engine/install/). В корне этого репозитория:

```bash
docker compose up --build -d
```

Откройте [http://localhost:8000](http://localhost:8000). Вставьте ссылку, выберите число/длительность клипов, подтвердите права на обработку и нажмите **«Найти моменты»**.

Первые задачи будут медленнее: образ скачивается один раз, а Whisper при первом запуске загрузит выбранную модель в `data/.cache`. После этого ни аудио, ни транскрипт, ни рендер не отправляются в внешний AI-сервис.

Полезные команды:

```bash
# Смотреть обработку
 docker compose logs -f clipper

# Остановить сервис (результаты в ./data сохранятся)
 docker compose down

# Полностью удалить результаты и кэш моделей
 rm -rf data
```

### Рекомендуемая конфигурация машины

| Сценарий | Минимум | Комфортно |
|---|---:|---:|
| Один CPU-ролик 720p | 8 GB RAM, 4 потока CPU | 16 GB RAM, 8+ потоков CPU |
| Whisper `small` | ~2 GB свободной RAM сверх видео | 4+ GB свободной RAM |
| Локальная Ollama `qwen2.5:7b` | 12 GB RAM | 16 GB RAM или GPU |
| Место на диске | 5 GB | 20+ GB |

Длительный стрим лучше сначала обрезать до нужного VOD или запускать на машине с достаточным диском. По умолчанию одновременно работает одна задача — это специально, чтобы не исчерпать память CPU-сервера.

## Более умный, но всё ещё бесплатный выбор моментов: Ollama

Эвристика работает и без модели. Чтобы редактор дополнительно понял контекст, сарказм и неловкие диалоги, можно поднять полностью локальную LLM:

```bash
# 1. создать .env из примера и добавить две строки
cp .env.example .env
# LOCAL_LLM_URL=http://ollama:11434/v1
# LOCAL_LLM_MODEL=qwen2.5:7b

# 2. поднять сервисы и локальный Ollama
 docker compose --profile ai up -d --build

# 3. один раз скачать свободную модель
 docker compose exec ollama ollama pull qwen2.5:7b

# 4. перезапустить обработчик, чтобы он прочитал .env
 docker compose restart clipper
```

Ollama не обязательна для **Clip Finder**: если контейнер модели недоступен или вернул некорректный ответ, задача не ломается — приложение записывает это в журнал и использует локальный скоринг Whisper. Для слабого компьютера оставьте `LOCAL_LLM_URL` пустым.

Для **Story Studio** Ollama обязательна: без локальной языковой модели приложение намеренно не будет придумывать сценарий. Это исключает скрытую отправку темы в облачный API и делает требование к модели понятным в интерфейсе.

## Story Studio: идея → ролик

1. Откройте вкладку **Story Studio** в браузере с телефона или компьютера.
2. Опишите идею и выберите формат: вымышленная история, вдохновляющий сюжет или безопасная загадка.
3. Укажите язык, примерную длину и визуальный тон.
4. Подтвердите, что при публикации вы оставите маркировку AI-assisted и не будете выдавать вымысел за реальную историю.
5. Получите локально сгенерированные `story-reel.mp4`, `story.srt`, `narration.wav` и `content-pack.txt`.

Story Studio не использует фото или голоса реальных людей, не клонирует чей-либо голос и не скрапит чужие истории. Визуальная часть — оригинальные редакционные сюжетные карточки, созданные на сервере из сценария. Это надёжнее, чем автоматически брать чужие ролики, но это не генератор реалистичных AI-актёров.

### Более естественная локальная озвучка с Piper

Docker-образ сразу включает полностью автономный fallback **eSpeak NG**. Он работает на любом старте, но звучит синтетически. Для роликов, где важна естественность, положите совместимые с Piper файлы `<voice>.onnx` и `<voice>.onnx.json` в `data/voices/`, затем добавьте в `.env`:

```dotenv
PIPER_VOICE_MODEL=/data/voices/ru_RU-your-voice-medium.onnx
# PIPER_SPEAKER=   # только если выбранная модель многоголосая
```

После `docker compose restart clipper` новый Story Reel автоматически выберет Piper. Используйте только модели и голоса с подходящей лицензией; не имитируйте и не клонируйте голос человека без его явного согласия.

## Настройка

Скопируйте `.env.example` в `.env` только если требуется поменять defaults:

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `WHISPER_MODEL` | `small` | Локальная модель речи. `base` быстрее, `medium` точнее, но тяжелее. |
| `MAX_WORKERS` | `1` | Количество одновременно обрабатываемых видео. Поднимайте только при достаточной RAM. |
| `LOCAL_LLM_URL` | пусто | OpenAI-совместимый адрес вашей локальной Ollama/LM Studio/vLLM, например `http://ollama:11434/v1`. |
| `LOCAL_LLM_MODEL` | `qwen2.5:7b` | Название уже скачанной локальной LLM. |
| `YTDLP_COOKIES_FILE` | пусто | Путь в контейнере к Netscape cookie-файлу только для роликов, к которым у вас есть законный доступ. |
| `PIPER_VOICE_MODEL` | пусто | Абсолютный путь **в контейнере** к вашей локальной Piper `.onnx` voice model. Если не задан, Story Studio использует eSpeak NG. |
| `PIPER_SPEAKER` | пусто | Необязательный ID спикера для многоголосой Piper-модели. |

### Видеодоступ и cookies

Платформы периодически меняют антибот-проверки. Сервис использует актуальный `yt-dlp`, но не обходит DRM, приватность, платный доступ или ограничение автора. Для собственных/разрешённых роликов, которые YouTube даёт посмотреть лишь после входа, обновите образ и смонтируйте экспортированный Netscape cookie-файл в `./data/cookies.txt`, затем укажите в `.env`:

```dotenv
YTDLP_COOKIES_FILE=/data/cookies.txt
```

Никогда не публикуйте cookies и не добавляйте их в Git.

## Что происходит с задачей

1. URL проверяется: принимаются только `youtube.com`, `youtu.be` и `twitch.tv` по HTTPS.
2. `yt-dlp` скачивает один доступный ролик (плейлисты намеренно отключены).
3. `ffprobe` валидирует видео; `faster-whisper` локально создаёт слова с временными метками.
4. Алгоритм строит цельные разговорные окна 10–150 секунд, оценивает реакции, темп и признаки смеха. При включённой Ollama та ранжирует этот shortlist по смыслу.
5. FFmpeg делает вертикальную версию: полный исходный кадр размещается над размытым фоном, поэтому важная часть широкого видео не отрезается по центру.
6. Временные метки слов превращаются в `.srt` и красивые подписи, затем FFmpeg вшивает их в MP4.

Для Story Reel поток другой: локальная Ollama возвращает строго проверяемый JSON-сценарий, Piper/eSpeak создаёт WAV, Pillow рисует оригинальные сюжетные карточки, FFmpeg склеивает вертикальный MP4 и вшивает субтитры. В результатах есть `content-pack.txt`, чтобы не переписывать вручную заголовок, описание и хэштеги.

Файлы задачи находятся в `data/jobs/<id>/`: для нарезки — `source/`, `transcript.txt`, `transcript.json`, `output/*.mp4`, `output/*.srt`; для Story Reel — `story-script.json`, `output/story-reel.mp4`, `output/narration.wav`, `output/story.srt`, `output/content-pack.txt`. Они игнорируются Git.

## Ограничения, о которых важно знать

- Модель может ошибиться в юморе — это рекомендация, а не обещание, что каждый выбранный фрагмент будет смешным. Локальная Ollama заметно улучшает выбор там, где важен контекст.
- Для качественного распознавания нужен слышимый голос. Музыка, тишина, шум и непонятная речь дают меньше хороших кандидатов.
- Это обработчик опубликованных видео/VOD, а не запись живого эфира. Закончившийся Twitch VOD обработается нормально; бесконечный live лучше сначала сохранить законным способом.
- Центрирование не заменяет профессиональное face tracking. Его плюс — в кадре не теряется собеседник или демонстрация экрана.
- Нельзя обещать «без ошибок»: сеть, правила площадок, свободное место и ресурсы компьютера могут дать сбой. Интерфейс оставляет понятный журнал задачи, а обработчик не зависает в статусе «в процессе» после перезапуска.
- Story Studio рассчитан на оригинальные вымышленные/развлекательные сценарии. Результат LLM требует просмотра человеком: модель может написать банальный, неточный или неподходящий для аудитории текст.
- eSpeak NG — функциональный офлайн-fallback, а не студийная дикторская запись. Подключите лицензированную Piper-модель, если качество голоса критично.

## Доход, автоматизация и честная публикация

ClipLab снимает механическую работу: сценарий, озвучка, субтитры, MP4 и текст публикации собираются в одном месте. Но он **не обещает доход, просмотры, монетизацию или «вирусность»** — это зависит от качества, ниши, аудитории, правил и решений платформы.

В приложении сознательно нет бездумного автопостинга и массовой рассылки: они часто нарушают правила платформ, ухудшают качество канала и могут привести к ограничениям. Практичный workflow для устойчивого канала:

1. Создать несколько черновиков и выбрать один, который действительно подходит аудитории.
2. Перед публикацией проверить сценарий, звук, субтитры, фактические утверждения и права на каждый использованный материал.
3. Оставить понятную маркировку AI-assisted/сгенерировано с помощью ИИ, особенно для вымышленных историй.
4. Адаптировать заголовок и хэштеги из `content-pack.txt` под конкретную площадку, а не публиковать одинаковый спам.
5. Смотреть на удержание и комментарии, улучшать следующие ролики на основе реакции аудитории.

Так автоматизация помогает выпускать больше оригинального контента с меньшими усилиями, не вводя зрителей и платформы в заблуждение.

## Права и правила площадок

Обрабатывайте только собственные видео, видео с явным разрешением автора или материалы, на которые у вас есть соответствующие права. Соблюдайте условия YouTube/Twitch и местное авторское право. Интерфейс требует это подтвердить перед запуском; техническая возможность скачать URL не является разрешением на его повторное использование.

## API для локальной автоматизации

| Метод | Маршрут | Результат |
|---|---|---|
| `POST` | `/api/jobs` | Поставить URL в очередь |
| `POST` | `/api/stories` | Поставить оригинальный Story Reel в очередь (нужна локальная LLM) |
| `GET` | `/api/jobs` | Все локальные задачи |
| `GET` | `/api/jobs/{id}` | Статус, журнал, клипы |
| `GET` | `/api/jobs/{id}/files/{filename}` | MP4 или SRT завершённой задачи |
| `DELETE` | `/api/jobs/{id}` | Удалить завершённую задачу и файлы |

Пример:

```bash
curl -X POST http://localhost:8000/api/jobs \
  -H 'content-type: application/json' \
  -d '{
    "source_url":"https://www.youtube.com/watch?v=VIDEO_ID",
    "clip_count":3,
    "min_seconds":20,
    "max_seconds":50,
    "render_height":720,
    "rights_confirmed":true
  }'
```

## Разработка без Docker

Нужны Python 3.11+, системные `ffmpeg`/`ffprobe` и шрифт DejaVu Sans:

```bash
python -m venv .venv
. .venv/bin/activate       # Windows: .venv\Scripts\activate
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

Переменная `DATA_DIR=./data` используется по умолчанию. Не храните результаты на диске, который браузер или веб-сервер могут раздавать напрямую.
